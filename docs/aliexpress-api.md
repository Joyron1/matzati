# AliExpress Affiliate API: verified behavior

What we confirmed for M2 (CLAUDE.md §5.3) and for the product-page, coupons, sales and attribution
research of 2026-09-28, with how we know it. Re-verify with `npm run check:ali` (3 calls),
`scripts/probe-aliexpress.ts` (5 calls), `scripts/probe-product-extras.ts` (at most 15 requests;
masked fixtures in `fixtures/aliexpress/probe-extras/`) and `scripts/probe-hot.ts` (at most 6 calls;
masked fixtures in `fixtures/aliexpress/probe-hot/`).

"Doc N" is `https://openservice.aliexpress.com/doc/doc.htm#/?docId=N`. Method docs were read through
the JSON behind the doc site (`/handler/share/apidoc/getApi.json?path=<method>`). "authType 0" means
the method works with the app key and secret alone, like all our calls; "authType 1" means it needs a
user `access_token` from the OAuth flow (docs 1590, 1364).

## Protocol

| Topic      | Finding                                                                                                                                                                                                                                       | Source                                                                                                           |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Gateway    | `POST https://api-sg.aliexpress.com/sync`, all params as `application/x-www-form-urlencoded`                                                                                                                                                  | Official doc 1385 + real calls                                                                                   |
| Signature  | Sort all sent params except `sign` by key (code-point order), concatenate `key+value`, HMAC-SHA256 with the app secret, uppercase hex. | Values     | Signed raw (not URL-encoded); empty values are neither sent nor signed                                                                                                                                                                        | Official SDK                                                                                                     |
| Timestamp  | Epoch milliseconds as a string                                                                                                                                                                                                                | Official SDK                                                                                                     |
| Errors     | Gateway errors: `{ error_response: { type, code, msg, sub_code?, sub_msg?, request_id } }`. Business errors: HTTP 200 with `resp_result.resp_code != 200`; `405` means empty result                                                           | Docs + real `InsufficientPermission` response                                                                    |
